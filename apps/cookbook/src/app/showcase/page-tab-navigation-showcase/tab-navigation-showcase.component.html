Tab Navigation is used to group related content, allowing users to browse content in sections without leaving the page. The content in each tab should be located at the same hierarchical level in the information architecture. Tab Navigation always contains at least two tabs, with one tab active at a time.

Default

Tab Navigation is designed for use within a page. On scroll, it remains fixed near the title area. It also becomes horizontally scrollable if items overflow.

Accessibility

Tab Navigation and Tab Navigation Item implement the tablist and tab aria pattern, as defined in the WAI-ARIA Authoring Practices .

To fully implement accessible tab navigation it is important to wire up the kirby tab navigation component with the content that is shown when a tab is selected. This can be done by using the aria-controls attribute on the tab navigation item, and aria-labelledby and tabpanel role attribute on the matching content as shown in the example above.

Please note: Only the active tabpanel should be visible to Assistive Technology. Non-active tabs should be hidden with display: none or omitted from the DOM.
